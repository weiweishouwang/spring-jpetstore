| 分类 | 含义 | 开发与验收方式 |

## 2. 产品目标与范围

### 2.1 产品目标

用户能够浏览宠物商品、搜索产品、维护购物车、注册登录、填写账单及收货地址和模拟卡片信息、确认提交订单，并查看自己的历史订单。

成功提交订单表示系统已记录交易，不表示真实支付成功、已发货或已完成履约。

### 2.2 本期业务范围

| 模块 | 包含的能力 |
| --- | --- |
| 账户 | 注册、用户名密码登录、退出、本人资料修改、可选修改密码 |
| 商品目录 | 分类导航、产品列表、可售项列表及详情、产品名称搜索 |
| 购物车 | 游客及登录用户加购、同规格合并、修改数量、移除、金额计算、会话隔离 |
| 结算 | 登录校验、默认地址、独立收货地址、模拟卡片信息、确认提交 |
| 订单与库存 | 创建订单、提交时扣库存、事务一致性、本人订单列表及详情 |
| 个性化 | 偏好分类、推荐列表开关、横幅开关、语言偏好保存 |

### 2.3 不在现有业务范围内

不包括管理后台、商品发布或上下架操作、供应商管理、找回密码、邮箱验证、第三方登录、手动收藏、智能推荐、真实支付、退款、发货、签收、取消、退换货、发票、优惠券、折扣、运费或税费计算、多币种结算。

这些能力没有在当前仓库中形成完整实现，不能随技术升级默认加入。若需要，应单独定义需求及验收。缺货预订是否保留属于 Q02；不能从缺货文案推导出完整预订业务。

## 4. 核心用户流程

### 4.1 注册与账户维护

1. 用户进入注册页，输入账户、联系资料、地址及偏好。
2. 系统校验输入；失败则反馈字段错误，不创建部分账户数据。
3. 成功后进入登录页，用户显式登录。
4. 登录用户可编辑本人资料；用户名不可修改；新密码留空表示不改密。

### 4.2 浏览与购物车

1. 用户从分类进入产品，再查看可售项详情；也可按产品名称搜索。
2. 加购以可售项为单位；重复添加同一项累加数量。
3. 在购物车修改数量或移除商品，系统同步更新明细金额和小计。
4. 加购不预占或扣减库存；有货提示不代表提交时库存一定充足。

### 4.3 结算与下单

1. 从购物车进入结算；未登录用户先登录。
2. 系统用当前账户资料初始化账单地址和收货地址。
3. 用户填写模拟卡片信息并修改账单地址；可选择另填收货地址。
4. 用户核对地址并确认提交；确认前不写订单、不扣库存。
5. 提交时执行服务端校验，按已确定的价格、库存策略创建订单。
6. 订单、状态、明细及库存变更一致提交；成功后可进入本人订单详情。
7. 成功后购物车的清理范围按 Q04 执行，失败不得丢失未成交内容。

当前未选择独立收货地址时，收货地址仍来自已有表单值，不会随账单地址修改自动同步。是否改为“收货地址始终等于最终账单地址”，应作为显式业务变化记录，不能在迁移中静默改变。

### 4.4 历史订单

用户进入“我的订单”，查看本人订单摘要，再打开详情。直接使用他人订单号访问时，系统必须拒绝且不返回他人订单内容。

## 6. 数据与输入规范

### 6.1 账户字段兼容基线

### 6.3 现有存储结构

| 业务域 | 现有表 | 主要关联 |
| --- | --- | --- |
| 账户 | account、signon、profile | 用户名/用户编号逻辑关联 |
| 分类与商品 | category、product、item、supplier | 分类→产品→可售项，可售项关联供应商 |
| 个性化 | bannerdata | 以偏好分类关联横幅 |
| 库存 | inventory | 按可售项编号关联 |
| 订单 | orders、orderstatus、lineitem | 订单关联状态和多条明细 |
| 编号辅助 | sequence | 当前维护 ordernum |

共 13 张表。完整字段、实际外键、索引和初始数据见 [数据结构基线](baseline/data-model.md)。用户名相关长度不统一；多数账户/订单关联没有数据库外键，不能把逻辑关系当作已受外键保护。

现已确认结算采用 CNY、两位小数、HALF_UP，商品售价大于零，总额上限99,999,999.99。旧页面 `$` 仅为历史展示，改造后不继续作为币种标识。

演示脚本包含 2 个账户、5 个分类、16 个产品、28 个可售项，库存各 10000，ordernum 从 1000 开始，无初始订单。这些值仅用于演示和回归，不是固定业务要求。

## 7. 一致性与质量要求

| 编号 | 分类 | 可验收的业务结果 |
| --- | --- | --- |
| NFR-01 | 保留 | 注册、资料更新及下单分别保持整体一致；写入失败不得形成部分账户或订单。现有默认事务已覆盖的异常类型不等于所有失败路径均已验证。 |
| NFR-02 | 纠正 | 所有访问本人数据及写入操作均受服务端授权和输入校验控制，不依赖隐藏按钮或页面字段；读取操作不得触发业务写入。 |
| NFR-03 | 纠正 | 同一次下单确认的重复提交、重试最多产生一张订单和一次库存扣减；并发订单标识唯一。 |
| NFR-04 | 纠正 | 密码不明文存储，不向页面或接口回显密码/哈希；重复密码仅用于输入确认。 |
| NFR-05 | 纠正 | 商品描述和横幅不得执行非预期脚本；错误信息不得泄露内部异常或凭据。需明确允许内容格式后验证。 |
| NFR-06 | 待决策 | 是否承载真实用户、账户/订单持久化、历史数据迁移及保留期限见 Q12；H2 内存演示配置不构成正式数据可丢失的许可。 |
| NFR-07 | 待决策 | 性能、并发量、可用性、数据规模、备份及恢复目标须根据实际使用确定，不设置缺乏依据的数值指标。 |

## 8. 异常与边界要求

“目标”中超出现状的处理属于纠正项；尚未实测的路径须补验收，不应描述为已具备。

| 场景 | 目标结果 | 当前证据/依赖 |
| --- | --- | --- |
| 注册或编辑输入不合法 | 显示字段错误，不保存无效修改 | 注册选定场景已实测；完整字段组合未覆盖 |
| 用户名重复 | 拒绝且不覆盖原账户，提供冲突提示 | 数据拒绝已实测，专用提示待补齐 |
| 密码错误 | 认证失败，不建立登录身份 | 已实测 |
| 未登录访问账户编辑/订单 | 要求登录，不能返回受保护业务数据 | 选定入口已实测；登录后恢复上下文待浏览器验证 |
| 访问他人订单 | 拒绝，不返回对方订单内容 | 已实测 |
| 分类/产品/可售项/订单不存在 | 稳定的未找到反馈，不暴露异常栈 | 现有空值处理不足，待补齐 |
| 非法数量或空订单 | 写入前拒绝，不创建订单、不变更库存 | 空订单可持久化缺陷已复现，目标未实现 |
| 库存不足 | 按 Q02 的预订/拒绝规则处理，不能出现未经定义的负库存 | 负库存缺陷已复现 |
| 下单写入中途失败 | 不留下部分订单、状态、明细或库存变更 | 第二条明细失败的回滚路径已实测 |
| 重复提交或并发创建 | 满足 NFR-03，失败不得重复扣库存 | 静态发现风险，尚未进行并发及重试实测 |
| 缺少横幅/无效偏好 | 缺失展示内容不应使合法账户无法认证；偏好须校验允许值 | 当前横幅内连接可能影响账户查询，待纠正 |
| 历史商品改价或删除 | 成交金额不变；商品文本缺失时的展示按 Q15 | 改价影响明细小计已在模型重关联场景复现；删除场景未实测 |
| 成功/失败后重新进入购物车 | 失败保留未成交内容，成功按 Q04 清理 | 真实会话生命周期尚未验证 |
