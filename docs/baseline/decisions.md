# 行为保留与缺陷纠正清单

本阶段只建立基线，不修正业务实现。本页给出迁移验收方向：明确的错误应纠正；业务策略变化仍按 [需求规范](../spec.md) 的 Q 编号单独确认。

## 1. 应保留的业务行为

| 编号 | 保留内容 | 关联规则/回归 |
| --- | --- | --- |
| KEEP-01 | 注册建立账户、凭据、偏好，校验失败不写入；注册成功后显式登录 | ACC-01～05、Web 注册/登录测试 |
| KEEP-02 | 用户名唯一、不可修改；资料编辑仅本人；空密码不改密 | ACC-02、07～09、Service 账户测试 |
| KEEP-03 | 公共目录按分类→产品→可售项展示；搜索产品名且不区分大小写 | CAT-01～05、Web 目录测试 |
| KEEP-04 | 游客可加购、同可售项数量累加、不同规格分行、会话隔离 | CRT-01～03、Web 购物车测试 |
| KEEP-05 | 购物车数量影响小计；显式移除即时生效；加购不扣库存 | CRT-08～10、Web 购物车测试 |
| KEEP-06 | 登录后才下单，订单归属来自当前身份；下单地址与账户资料分开 | ORD-01～03、Web 结算测试 |
| KEEP-07 | 确认后才持久化；订单、明细、状态及库存事务一致 | ORD-05、10、Service 订单回滚测试 |
| KEEP-08 | 用户只看到自己的订单列表及详情 | ORD-17～18、Web 订单归属测试 |
| KEEP-09 | 支付为模拟；偏好分类推荐不等同于手动收藏 | ORD-04～05、PER-01～04；浏览器待验证 |

保留业务效果不要求保留旧 URL、Session 对象结构、明文密码、数据库编号算法或框架配置方式。接口变化需要迁移兼容方案。

## 4. 特征测试如何处理

`LegacyKnownDefectTest` 的通过表示成功复现错误，不表示这些错误是永久的兼容要求。修复对应缺陷时：

1. 对照本页和 [需求规范](../spec.md) 确定目标行为及是否需要业务决策。
2. 将该测试的旧行为断言改为目标不变量，迁入正常回归类，保留缺陷编号便于追踪。
3. 执行完整正常回归，验证其他保留行为未退化。
4. 更新 [需求规范](../spec.md) 中的当前状态与本页证据，保留历史问题记录。

不能把特征测试删掉或永久跳过后直接认定修复成功。MockMvc 未覆盖的 JSP 文案、真实 HTTP 会话及浏览器流程仍须按 README 的清单完成验证。
